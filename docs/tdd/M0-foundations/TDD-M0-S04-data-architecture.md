# TDD-M0-S04: Data Architecture Decision

**Milestone:** M0 Foundations
**Status:** ⚠️ Decision made (ADR-0005) but not fully executed
**Gaps:** G-02, G-08, G-12

## Story

As a **developer**, I want the data architecture decision finalized and reflected in the codebase, so that there are no phantom dependencies and the "no storage" promise is enforceable from the start.

## Context

The project has **two contradictory signals**:

1. **ADR-0005** (decided): "No server-side message storage." Bans, sessions, reports — all in memory.
2. **package.json** (current): still lists `better-sqlite3` and `@types/better-sqlite3` as dependencies.

Open decisions D-05 ("keep SQLite?") and D-09 ("SQLite history → session-only?") are both ⏸, but the architecture docs, privacy docs, threat model, and LLD all assume no database.

## Decision (assumed, pending PO confirmation)

**Remove `better-sqlite3` and `@types/better-sqlite3` from package.json.**

Rationale:
- ADR-0005 explicitly says "no server-side message storage"
- The privacy-and-sessions.md data inventory shows no database
- The LLD module layout has no `db/` directory
- Keeping an unused 10+ MB native dependency increases install time, audit surface, and cognitive load

## Technical Design

### What Gets Removed

```bash
npm uninstall better-sqlite3 @types/better-sqlite3
```

### What Replaces It

All server-side state lives in **memory** via typed Maps with TTL:

| Data | Structure | TTL | Module |
|---|---|---|---|
| Client state | `Map<socketId, ClientState>` | Until disconnect | `sessions/sessionManager.ts` |
| Sessions | `Map<sessionId, Session>` | Until session ends | `sessions/sessionManager.ts` |
| Waiting pool | `Map<socketId, WaitingEntry>` | Until matched/left | `matchmaking/matchmaker.ts` |
| IP hash bans | `TtlMap<ipHash, BanRecord>` | 24 h | `safety/banList.ts` |
| Reports | `TtlMap<ipHash, ReportRecord>` | 24 h | `safety/reports.ts` |
| No-rematch | `TtlMap<pairKey, true>` | 24 h | `safety/noRematch.ts` |
| Rate limit buckets | `Map<key, TokenBucket>` | Until socket disconnect / TTL | `security/tokenBucket.ts` |

The `lib/ttlMap.ts` module provides a `Map` with automatic expiry, used by bans, reports, and no-rematch. It uses `Clock` (injectable for tests).

### Data Loss on Restart

When the server restarts (deploy, crash, Render sleep):
- All sessions end — clients reconnect and get new sessions
- All bans reset — accepted trade-off for a free-tier single-instance setup
- All rate limit state resets

This is acceptable because:
- Sessions are ephemeral by design (no persistent identity)
- Bans are short (24h) and probabilistic (IP-based)
- Restarts are infrequent (deploys, Render sleep/wake)

### Scaling Seam

The LLD defines `SessionStore`, `WaitingPool`, and `TtlStore` as interfaces. When scaling to multiple instances, Redis implementations replace the in-memory ones. See `docs/06-operations/scaling.md`.

## Test Plan (TDD)

1. **No import of `better-sqlite3` anywhere:** `grep -r "better-sqlite3" src/` returns nothing
2. **No `db/` directory exists:** `ls src/db/` fails
3. **`npm ci` installs without native compilation warnings** (better-sqlite3 requires node-gyp)
4. **`npm run build` succeeds** without SQLite references
5. **TtlMap unit tests:**
   - `set(key, value, ttlMs)` → `get(key)` returns value
   - After TTL expires (fake clock advance) → `get(key)` returns undefined
   - `delete(key)` removes immediately
   - `size` reflects only non-expired entries
   - `cleanup()` purges expired entries
