# ADR-0006: Anonymous: no accounts, no JWT, system-generated names

- **Status:** Accepted · **Date:** 2026-10-08

## Context
Users must be anonymous, **even to the operators**. Names are generated by the system. The question was raised: *"Do we use JWT?"*

## Options
| Option | Pros | Cons |
|---|---|---|
| Accounts + JWT sessions | Persistent identity, bans by account | Contradicts anonymity; we'd store emails/passwords; JWT secret management; revocation is hard |
| Anonymous JWT (signed random id) | Survives reconnects across instances | Adds a signing secret and a token that *is* a persistent identifier; no benefit for one instance |
| **No tokens: identity = the live socket** | Nothing to steal, nothing to store, simplest | Identity ends when the connection ends (that's the goal) |

## Decision
No accounts, no JWT. A participant's identity is the live Socket.IO connection plus a random per-session name. Brief reconnects are handled by Socket.IO **connection state recovery** (30 s).

## Consequences
- ✅ No credentials to leak; nothing links two sessions together
- ⚠️ Bans can't target a person, only a daily-salted IP hash (ADR in trust-and-safety)
- 🔁 Revisit JWT **only** if we run multiple instances and need a signed, short-lived "session ticket" for cross-instance reconnects
